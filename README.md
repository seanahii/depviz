# depviz — визуализатор графа зависимостей пакетов Python

Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 28. Выполнил: Царев А.А., группа ИКБО-66-25.

## 1. Общее описание

`depviz` — CLI-приложение, которое строит граф зависимостей пакетов
Python (pip) и показывает его на языке диаграмм D2. Готовые менеджеры
пакетов и библиотеки для получения зависимостей не используются: данные
берутся из JSON API PyPI средствами стандартной библиотеки Python, а
строки требований PEP 508 разбираются вручную.

Возможности по этапам:

| Этап | Что сделано |
|------|-------------|
| 1 | Параметры из опций командной строки, проверка всех параметров |
| 2 | Прямые зависимости заданной версии пакета из PyPI |
| 3 | Транзитивный граф обходом DFS без рекурсии, фильтр по подстроке, циклы, тестовый репозиторий |
| 4 | Обратные зависимости (кто зависит от пакета) тем же алгоритмом обхода |
| 5 | Описание графа на языке D2, построение SVG и показ на экране |

## 2. Функции и настройки

### Опции командной строки

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) |
| `-r`, `--repo` | URL репозитория (`https://pypi.org/pypi`) или путь к файлу тестового репозитория (обязательно) |
| `-m`, `--mode` | режим работы с репозиторием: `real` (по умолчанию) или `test` |
| `-v`, `--version` | версия пакета, например `2.31.0` (обязательна в режиме `real`) |
| `-f`, `--filter` | не учитывать пакеты, имя которых содержит подстроку (без учёта регистра) |
| `--reverse` | вывести обратные зависимости пакета (режим `test`) |
| `--d2 FILE` | сохранить граф на языке D2 в файл и вывести его |
| `--show` | построить изображение (SVG) утилитой `d2` и открыть его; без `--d2` файл кладётся в `out/<пакет>.d2` |

Проверки параметров (при ошибке — сообщение `Ошибка: ...` в stderr
и код возврата 1):

- `--mode` — только `real` или `test`;
- `--package` — не пустое; в режиме `real` — допустимое имя пакета
  Python, в режиме `test` — только большие латинские буквы;
- `--repo` — в режиме `real` URL вида `http(s)://хост/путь`,
  в режиме `test` — существующий файл;
- `--version` — формат PEP 440 (`2.31.0`, `1.0rc1`, `1.0.post2`);
  в режиме `real` обязательна;
- `--filter` — непустая строка без пробелов; корневой пакет не должен
  попадать под фильтр.

### Получение зависимостей (этап 2)

Метаданные загружаются по адресу `<repo>/<пакет>/<версия>/json`
(например `https://pypi.org/pypi/requests/2.31.0/json`). Из поля
`info.requires_dist` извлекаются имя зависимости, ограничение версии
и маркер окружения. Зависимости с маркером `extra == "..."`
(необязательные группы, `pip install pkg[extra]`) не учитываются:
pip не ставит их по умолчанию. Имена нормализуются по PEP 503
(`Jinja2` → `jinja2`, `Foo_Bar` → `foo-bar`).

Для корневого пакета берётся заданная версия, для транзитивных
зависимостей — последняя версия в репозитории (запрос
`<repo>/<пакет>/json`). Если метаданные транзитивного пакета получить
не удалось, выводится предупреждение и пакет считается листом.

### Построение графа (этап 3)

Функция `build_graph` (`src/depviz/graph.py`) — обход в глубину
**без рекурсии**:

- стек хранит итераторы по зависимостям вершин текущего пути;
- на каждом шаге берётся следующая зависимость верхней вершины;
  когда зависимости кончились, вершина снимается со стека и
  помечается обработанной;
- ребро в вершину, которая уже лежит на текущем пути, — это
  **циклическая зависимость**: цикл запоминается, повторного входа нет,
  поэтому обход всегда завершается;
- уже обработанная вершина (например, общая зависимость двух пакетов)
  повторно не обходится;
- пакеты, имя которых содержит подстроку `--filter`, не посещаются.

Тест `test_deep_chain` проверяет цепочку из 5000 пакетов — рекурсия
на такой глубине упала бы с `RecursionError`.

### Тестовый репозиторий

Режим `--mode test`: вместо URL указывается текстовый файл, где пакеты
называются большими латинскими буквами:

```text
# комментарий
A: B C
B: D
C: D E
D:
```

Слева от двоеточия — пакет, справа — его прямые зависимости через
пробел или запятую. Пакет, который упоминается, но не описан, считается
пакетом без зависимостей. Примеры лежат в `examples/`:

| Файл | Что демонстрирует |
|------|-------------------|
| `simple.txt` | ромб: D достижим через B и через C |
| `cycle.txt` | цикл A → B → C → A и петля E → E |
| `big.txt` | 13 пакетов, цикл B → F → J → B, пакет M вне графа A |
| `missing.txt` | ссылка на неописанный пакет Z |
| `bad.txt` | ошибка формата (имя в нижнем регистре) |

### Обратные зависимости (этап 4)

Опция `--reverse` выводит пакеты, которые прямо или транзитивно
зависят от `--package`. Граф тестового репозитория обращается
(`invert`: для каждого пакета — список тех, кто от него зависит), и по
нему запускается тот же нерекурсивный DFS (`reverse_dependencies`
вызывает `build_graph`). Фильтр и обработка циклов работают так же.

Режим доступен только для тестового репозитория: PyPI не хранит список
пакетов, зависящих от данного, а скачивать метаданные всех сотен тысяч
пакетов индекса ради одного запроса нереально.

### Визуализация (этап 5)

Модуль `src/depviz/d2.py` формирует описание графа на языке D2:
корневой пакет выделен заливкой, рёбра циклов — красным, в режиме
`real` у вершин подписаны версии. Опция `--show` вызывает утилиту
[`d2`](https://d2lang.com), получает SVG и открывает его программой
просмотра по умолчанию (на macOS — в браузере).

### Модули

| Модуль | Назначение |
|--------|-----------|
| `cli.py` | разбор опций, запуск режимов, вывод ошибок |
| `config.py` | класс `Config` и проверки `validate_*` |
| `pypi.py` | `fetch_json`, `parse_requirement`, `direct_requirements` |
| `sources.py` | источники зависимостей `PyPISource`, `FileRepoSource` |
| `testrepo.py` | разбор файла тестового репозитория |
| `graph.py` | `build_graph`, `reverse_dependencies`, текстовый вывод |
| `d2.py` | `to_d2`, `render`, `show` |

## 3. Сборка и тесты

Нужен Python 3.10+; сторонние пакеты не используются. Для показа
изображения нужна утилита `d2`:

```sh
brew install d2                 # macOS
make test                       # модульные тесты (сеть подменяется)
./run.sh --help                 # справка
make demo                       # демонстрация этапа 5 (нужны сеть и d2)
make clean                      # удалить out/ и кэш Python
```

### Сравнение со штатными инструментами

Штатный инструмент визуализации для pip — `pipdeptree`, который
показывает дерево зависимостей установленных пакетов (`--graph-output
svg` рисует его через Graphviz):

```sh
python3 -m venv /tmp/cmp && . /tmp/cmp/bin/activate
pip install flask==3.0.0 pipdeptree
pipdeptree -p flask
pipdeptree -p flask --graph-output svg > flask-pipdeptree.svg
```

Причины расхождений с `depviz`:

1. **Маркеры окружения.** pip и `pipdeptree` вычисляют маркеры
   (`python_version`, `sys_platform`, `platform_system`) и показывают
   только то, что реально установлено. `depviz` маркеры не вычисляет и
   показывает все обязательные зависимости. Например, у `flask` 3.0.0
   зависимость `importlib-metadata` помечена `python_version < "3.10"`,
   поэтому на Python 3.10+ pip её не ставит и в `pipdeptree` её нет,
   а `depviz` рисует её вместе с её собственными зависимостями
   (`zipp` и другими).
2. **Версии.** `depviz` берёт для транзитивных пакетов последнюю версию
   в PyPI, а pip выбирает новейшую версию, *удовлетворяющую
   ограничениям*, и `pipdeptree` показывает фактически установленную.
   Если последняя версия выходит за ограничение (например, `requests`
   2.31.0 требует `urllib3<3`), набор зависимостей может отличаться.
3. **Дерево против графа.** `pipdeptree` выводит дерево и повторяет
   общую зависимость под каждым родителем (`markupsafe` под `jinja2`
   и под `werkzeug`); у `depviz` это одна вершина с двумя входящими
   рёбрами.
4. **Несколько строк для одного пакета.** В метаданных `pandas` есть
   несколько требований `numpy` с разными маркерами `python_version`;
   pip выбирает одно, `depviz` объединяет их в одну вершину.
5. **Имена.** `depviz` нормализует имена по PEP 503 (`jinja2`),
   `pipdeptree` выводит их как в метаданных (`Jinja2`).
6. **Extras** не показывают оба инструмента, пока пакет не установлен
   с дополнительными группами (`pip install requests[socks]`).
