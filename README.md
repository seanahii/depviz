# depviz — визуализатор графа зависимостей пакетов Python

Практическая работа №2 по дисциплине «Конфигурационное управление», вариант 28.
Выполнил: Царев А.А., ИКБО-66-25.

## Общее описание

`depviz` — CLI-приложение, которое строит граф зависимостей пакетов
Python (pip). Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются — только стандартная библиотека Python.

Текущий этап: **4 — дополнительные операции**.

## Как получаются зависимости

Данные берутся из JSON API репозитория PyPI:
`<repo>/<пакет>/<версия>/json`, например
`https://pypi.org/pypi/requests/2.31.0/json`. Из поля
`info.requires_dist` (строки формата PEP 508) извлекаются имена
зависимостей, ограничения версий и маркеры окружения. Зависимости
с маркером `extra == "..."` — необязательные группы (`pip install
pkg[extra]`) — не учитываются, так как pip не ставит их по умолчанию.
Имена нормализуются по PEP 503 (`Foo_Bar` → `foo-bar`).

## Граф зависимостей

Граф строится с учётом транзитивности обходом в глубину (DFS)
**без рекурсии** (`src/depviz/graph.py`, функция `build_graph`):

- стек хранит итераторы по зависимостям вершин текущего пути;
- на каждом шаге берётся следующая зависимость верхней вершины стека;
  когда зависимости кончились — вершина снимается со стека и
  помечается обработанной;
- ребро в вершину, которая уже лежит на текущем пути, — это
  **циклическая зависимость**: цикл запоминается, повторного входа нет,
  поэтому обход всегда завершается;
- пакеты, имя которых содержит подстроку `--filter` (без учёта
  регистра), не посещаются и не попадают в граф.

В режиме `real` для корневого пакета берётся заданная версия,
для транзитивных зависимостей — последняя версия в репозитории
(подробнее о расхождениях с pip — в разделе этапа 5).

## Обратные зависимости

Опция `--reverse` выводит пакеты, которые зависят (напрямую или
транзитивно) от пакета `--package`. Граф тестового репозитория
обращается (`invert`: для каждого пакета — список тех, кто от него
зависит), и по нему запускается тот же нерекурсивный DFS из этапа 3
(`reverse_dependencies` вызывает `build_graph`). Фильтр и обработка
циклов работают так же.

Режим доступен только для тестового репозитория: у PyPI нет списка
пакетов, зависящих от данного, а перебрать все ~600 тыс. пакетов
индекса нереально.

## Тестовый репозиторий

Режим `--mode test`: вместо URL указывается путь к текстовому файлу,
где пакеты называются большими латинскими буквами:

```text
# комментарий
A: B C      # A зависит от B и C
B: D
C: D E
D:
```

Пакет, который упоминается, но не описан, считается пакетом без
зависимостей (выводится предупреждение). Готовые примеры — в каталоге
`examples/`.

## Параметры (опции командной строки)

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательно) |
| `-m`, `--mode` | режим работы с репозиторием: `real` (по умолчанию) или `test` |
| `-v`, `--version` | версия пакета (обязательна в режиме `real`) |
| `-f`, `--filter` | подстрока для фильтрации пакетов |
| `--reverse` | вывести обратные зависимости (режим `test`) |

Проверки параметров:

- `--mode` — только `real` или `test`;
- `--package` — не пустое; в режиме `real` — допустимое имя пакета Python,
  в режиме `test` — только большие латинские буквы;
- `--repo` — в режиме `real` URL вида `http(s)://хост/путь`,
  в режиме `test` — существующий файл;
- `--version` — формат версии PEP 440 (например `2.31.0`, `1.0rc1`);
- `--filter` — непустая строка без пробелов.

При ошибке выводится сообщение `Ошибка: ...` в stderr и код возврата 1.

## Сборка и тесты

Сторонние зависимости не нужны, достаточно Python 3.10+.

```sh
make test          # запуск тестов
./run.sh --help    # справка
```
